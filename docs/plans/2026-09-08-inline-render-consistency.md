# 内联译文挂载与完成统计一致性修复

## 问题与证据边界

用户在自定义 AI 翻译 gameseoradar.com/pricing 时，观察到标题内仍有 loading 占位，而 Popup 显示完成 39/39。HTML 不能证明是否发生克隆、内部替换或旧进度读取；本次不作网站特定归因。

## 实施范围

1. 内联渲染成功必须意味着当前版本的译文实际挂载在当前段落的有效目标内；仅原文元素仍连接不足以证明成功。
2. 原文文字不变而包装结构失效时，应重新处理该段落，撤销过期完成状态。
3. 克隆的插件标记不是有效的任务归属；局部清理无主占位、还原原始节点后再按可见性调度，不直接重写原文文本。
4. 正常扩展自身渲染不能引起重译循环；旧任务结果不能污染新挂载。
5. 恢复原文必须保留原始节点与事件，不遗留复制的 loading 或包装。
6. 失败与缺失结果也必须校验请求发起时的版本和任务身份，不能让旧失败覆盖同一段落的新成功状态。
7. 原文包装内新增控件等同文安全性变化必须有重新处理或错误收口路径，不能因渲染拒绝永久等待。

## 非目标

- 不改请求超时常量或加入超时设置；该需求独立保留。
- 不强制请求屏外内容，不增加周期性全页扫描或网站专用白名单。
- 不以本地回归通过声称已确认用户现场的唯一根因。

## 验收

- 保留 h2，替换内部 source/translation 节点后，旧结果不能被误记为挂载成功。
- 深克隆带 loading 或译文的内联段落，最终只有一份有效译文，无主占位被清理。
- 已完成后发生同文结构替换，当前任务恢复处理并最终收口。
- 本地扩展 E2E 同时检查渲染状态和进度统计，而非只检查请求返回。
- 单测、类型检查、构建预算和本地扩展回归均通过后交付 0.10.7。
- 累计预算原为项目内部的 48 KiB；用户确认本轮调整为 52 KiB，以容纳生命周期修复，各入口单独上限不变。不通过无关压缩或拆包规避总量检查。
