# 页面翻译长时间停留“翻译中…”与切换引擎无响应修复方案

## 一、问题背景

在 `v0.10.3` 中，用户反馈在某些网页（如 Vercel 文档）使用自定义 AI 或网络不稳定时：
1. 部分段落长久停留在“翻译中…”，等待很久都没有出现“翻译失败，请重试 ↻”按钮；
2. 在此期间尝试切换翻译引擎，页面重新渲染后依然长时间停留在“翻译中…”，感觉像死锁或无响应。

---

## 二、根本原因分析（Causal Chain）

### 1. 超时时间过长导致的“假死锁”体验
- 在 `src/content/main.ts:50` 中，`translate` 请求设置了 `95_000` 毫秒（95 秒）的硬超时。
- 当网络卡顿、代理挂起或 AI 服务无响应时，内容脚本处于 Promise 盲等状态（既不 Resolve 也不 Reject），长达 1.5 分钟内无法进入 `error` 状态，因此无法渲染重试按钮。

### 2. 切换引擎 / 重新翻译时新旧会话竞态与连接挂起
- 用户在 Popup 切换引擎时，会触发新的 `translate-page` 消息，进入新的代际（`generation`）。
- 旧请求依然在后台网络层或前端 Promise 中挂起，未被立即强行 Abort；
- 新会话开始后，所有段落重新挂上 `renderLoading`（“翻译中…”）；
- 当旧请求最终在 95 秒后超时失败时，因 `currentGeneration !== generation` 被静默丢弃，而新会话如果因相同网络原因或新配置问题再次挂起，导致用户看到页面再次进入新一轮漫长的 95 秒等待。

---

## 三、修复与优化方案

### 1. 调整前端超时阈值
- 将内容脚本前端单批翻译的通信超时从 `95_000` 毫秒缩短至合理的 **30,000 毫秒（30 秒）**。
- 一旦超过 30 秒无响应，立即抛出 `翻译请求超时，请检查网络或配置后重试`，使段落迅速转为失败状态并渲染 `↻` 重试按钮。

### 2. 切换会话时主动中止并清理在途请求
- 在 `src/content/index.ts` 的 `beginSession()` / `restore()` 中，确保不仅递增代际号，还要通过 `dependencies.cancel(previousTaskId)` 立即中止后台所有挂起的网络请求和流。
- 确保后台 `cancel-task` 能够精准 Abort 对应的 `AbortController`，立即释放连接池和资源。

### 3. 会话重置时保证 DOM 状态清理
- 在开始新一轮翻译前，确保上一轮的所有 loading / error 占位节点及 observer 任务完全清理，避免旧状态干扰新会话。

---

## 四、验证计划

1. **单元测试**：
   - 编写 `controller.test.ts` 测试：模拟请求超过 30 秒未响应，验证立即触发 `renderError` 并展示重试按钮。
   - 编写切换引擎时在途请求被主动 `cancel` 且不阻塞新引擎请求的测试。
2. **全量门禁**：
   - 运行 `npm test`、`npm run typecheck`、`npm run build` 确保所有 570+ 测试通过且体积达标。
3. **版本发布**：
   - 提升版本至 `0.10.4`，更新发布说明与相关文档。
