# 快捷键与触发方式设置

## Problem Frame

语层翻译目前有两套键盘触发机制，但信息分散且表达不准确：页面翻译由浏览器扩展命令管理，默认快捷键为 `Alt+A`；选区内联翻译由网页内容脚本识别，默认单击 `Ctrl`，并已在“划词翻译”栏目提供部分配置。

用户无法在设置页统一了解有哪些键盘操作、当前实际绑定是什么、应该在哪里修改。用户在 Chrome 中重新绑定页面翻译快捷键后，Popup 仍固定显示 `Alt+A`；新安装默认单击 `Ctrl` 还可能在 `Ctrl+C`、`Ctrl+V` 等组合键按下时提前触发内联翻译。

本次功能应建立统一、可信的“快捷键与触发方式”入口，而不是假装扩展能够直接修改所有浏览器快捷键。

---

## Actors

- A1. 普通阅读用户：希望快速翻译页面或选中文字，但不应因常用组合键产生意外翻译。
- A2. 键盘优先用户：希望知道当前真实快捷键，并能够方便地进入浏览器管理页重新绑定。
- A3. Chrome 或兼容的 Chromium 浏览器：负责注册、冲突处理和修改扩展命令快捷键。

---

## Key Flows

- F1. 查看并修改页面翻译快捷键
  - **Trigger:** 用户打开设置页的“快捷键与触发方式”栏目。
  - **Actors:** A2, A3
  - **Steps:** 设置页读取页面翻译命令的当前实际绑定并展示；用户点击修改入口；浏览器打开原生扩展快捷键管理页；用户在浏览器页面完成修改；返回设置页后重新展示最新绑定。
  - **Outcome:** 用户看到的快捷键与浏览器实际生效的绑定一致，并清楚知道修改由浏览器完成。
  - **Covered by:** R1, R3, R4, R5, R6, R7, R8, R9

- F2. 配置选区内联翻译触发
  - **Trigger:** 用户希望改变选中文字后的内联翻译触发方式。
  - **Actors:** A1, A2
  - **Steps:** 用户在统一栏目选择修饰键和触发次数；设置自动保存；选择普通网页文字后按所选方式触发；再次触发时移除现有内联译文。
  - **Outcome:** 用户可以在扩展内直接控制网页内快速触发，并能理解其适用范围和误触风险。
  - **Covered by:** R1, R2, R3, R10, R11, R12, R13, R14, R15

## Requirements

**统一入口与信息架构**

- R1. 设置页新增独立的“快捷键与触发方式”栏目，并在设置导航中提供对应入口。
- R2. 现有“选区内联翻译快捷键”和“触发次数”从“划词翻译”栏目迁移到新栏目；“划词翻译”栏目继续保留悬浮按钮和有限上下文设置。
- R3. 新栏目明确区分“浏览器快捷键”和“网页内快速触发”，解释两者由不同系统管理。

**浏览器快捷键**

- R4. 首期只展示现有的“切换当前页面翻译”命令，不新增翻译、恢复、重试、模式切换、引擎切换或专家切换命令。
- R5. 设置页必须展示浏览器当前实际启用的快捷键，而不是展示 Manifest 建议值或硬编码的 `Alt+A`。
- R6. 设置页提供显式按钮，让用户在一次主动点击后进入当前 Chromium 浏览器的原生扩展快捷键管理页；按钮附近说明快捷键需要在浏览器页面中修改。
- R7. 当页面翻译命令未分配快捷键时，设置页显示清晰提示，说明快捷键可能被清除或发生冲突，并将按钮文案调整为分配或修复快捷键。
- R8. 用户从浏览器快捷键管理页返回设置页后，页面应重新读取并展示最新绑定，无需重新加载扩展。
- R9. Popup 的翻译／显示原文按钮同步展示当前实际绑定；未分配时不显示虚假的默认键，并提供弱提示，不阻断按钮操作。

**网页内快速触发**

- R10. 选区内联翻译继续支持 `Ctrl`、`Alt`、`Shift`、`Win / Command` 和关闭，以及单击、双击、三击三种触发次数。
- R11. 新安装默认触发方式改为双击 `Ctrl`；已经保存过该配置的用户保持原值，不被迁移覆盖。
- R12. 用户选择单击模式时，设置页显示明确但不阻断的风险提示，说明它可能与复制、粘贴、菜单或系统快捷操作重叠。
- R13. 用户选择关闭时，触发次数控件应禁用或隐藏，避免出现“已关闭但仍选择双击”的矛盾状态。
- R14. 设置页说明内联触发只适用于普通网页文字，不响应输入框、密码框和可编辑区域；再次触发会移除译文。
- R15. 关闭划词悬浮按钮与关闭内联快捷触发继续保持两个独立设置，但界面必须让用户理解两者互不控制。

**内容一致性**

- R16. README、官网帮助、Popup 和当前版本用户文案中的页面翻译快捷键说明必须与实际绑定机制一致，不再把 `Shift+Alt+A` 或 `Alt+A` 写成永远不变的用户快捷键。
- R17. 历史设计与实现计划可以保留当时记录，但当前使用说明不得引用已经失效的默认键。

## Acceptance Examples

- AE1. **Covers R5, R8, R9.** Given 用户已在 Chrome 中把页面翻译改为 `Ctrl+Shift+Y`，when 用户打开或重新聚焦设置页和 Popup，then 两处都显示 `Ctrl+Shift+Y`，不显示 `Alt+A`。
- AE2. **Covers R7, R9.** Given 浏览器返回页面翻译命令的快捷键为空，when 用户查看设置页，then 页面显示未分配或冲突提示及修复入口；Popup 主按钮仍可点击，但只显示弱提示且不声称 `Alt+A` 可用。
- AE3. **Covers R6.** Given 用户点击“在浏览器中修改”，when 浏览器允许打开原生快捷键管理页，then 在新标签页进入对应管理页面；扩展设置页中不出现无法真正保存的按键录入框。
- AE4. **Covers R10, R11.** Given 新用户首次安装扩展，when 用户选择普通网页文字并只按一次 `Ctrl`，then 不触发内联翻译；在规定时间内再次按下 `Ctrl` 后触发。
- AE5. **Covers R11.** Given 旧用户已保存单击 `Alt`，when 扩展升级，then 仍保持单击 `Alt`，不会被改为双击 `Ctrl`。
- AE6. **Covers R12.** Given 用户选择单击任一修饰键，when 设置保存，then 界面显示可能与常用组合键重叠的风险提示，但允许用户继续使用该选择。
- AE7. **Covers R13.** Given 用户把触发键设为关闭，when 设置页更新，then 触发次数不可操作或不再展示；重新启用触发键后恢复可配置状态。
- AE8. **Covers R14, R15.** Given 用户关闭划词悬浮按钮但保留双击 `Ctrl`，when 用户选择普通网页文字并双击 `Ctrl`，then 内联翻译仍可触发，且设置页已明确说明这两个开关独立。

## Success Criteria

- 用户无需阅读外部文档即可说清页面翻译快捷键与选区内联触发的区别，以及各自在哪里修改。
- 设置页和 Popup 不再向已重绑或未分配快捷键的用户显示错误的 `Alt+A`。
- 新安装用户使用 `Ctrl+C`、`Ctrl+V` 等常用组合键时，不会因默认单击 `Ctrl` 提前触发内联翻译。
- 实现计划无需重新决定栏目归属、首期命令范围、默认触发方式、单击模式策略或未分配状态的提示层级。

---

## Scope Boundaries

- 首期不增加新的 Manifest command。
- 首期不支持在扩展设置页直接录制或写入浏览器管理的快捷键。
- 首期不把页面翻译快捷键改为扩展内容脚本监听，以免与网页快捷键、受限页面和键盘布局产生更大冲突。
- 首期不实现输入框选中文字翻译并替换；该能力落地时再评估为独立浏览器命令。
- `Escape` 关闭划词面板继续作为标准界面行为，不开放自定义。
- Popup、Options 和划词面板的 Tab、Enter、Space、方向键等原生控件操作不纳入产品快捷键列表。
- 不自动覆盖旧用户已经保存的内联触发偏好。

---

## Key Decisions

- 栏目命名为“快捷键与触发方式”：避免暗示所有按键都能在扩展内直接编辑。
- 采用统一栏目方案：集中展示两套机制，但清楚说明管理边界。
- 选区内联设置迁移到新栏目：避免同一配置出现双入口。
- 首期只整理现有命令：优先解决可发现性、真实性和误触问题，不扩张功能范围。
- 新安装默认双击 `Ctrl`：在易用性与常用组合键安全之间取平衡。
- 保留单击模式并显示风险提示：兼容已有用户和偏好明确的高级用户。
- 未分配时设置页强提示、Popup 弱提示：问题可见但不妨碍鼠标操作。

---

## Dependencies / Assumptions

- Chromium 浏览器允许用户通过其原生扩展快捷键管理页重新绑定 Manifest command。
- 浏览器可以向扩展返回当前命令及其实际启用的快捷键；空值代表当前未分配，但扩展无法获知具体由哪个应用或扩展造成冲突。
- 浏览器不提供由扩展直接修改命令绑定的 API，因此设置页只能展示状态并引导用户操作。
- 项目当前面向 Chrome 与兼容的 Chromium 浏览器；不同浏览器的原生管理页地址和打开行为在规划阶段核实。
